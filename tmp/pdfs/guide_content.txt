@@ Part 2 / Database and migration | Supabase, PostgreSQL, and pgvector
- **PostgreSQL is the database engine.** It stores relational records such as users, conversations, and messages. **Supabase is the platform hosting that database** and providing Auth and Edge Functions. **pgvector is an open-source PostgreSQL extension** that adds vector types and similarity operations inside Postgres. They are complementary layers, not three competing databases. [D1]
- **Example data:** a user row holds a name, machine brand/model, and Auth user ID. A conversation belongs to that application user. A message belongs to a conversation. A machine_docs row holds text, an embedding, a machine-model label, source information, and, for private learned content, an Auth owner.
- **Why use one database?** Profiles, ownership, and retrieved knowledge can share SQL filtering and operational tooling. A dedicated vector service could be considered later if measured scale or retrieval requirements justify the additional system.
## How ownership works in this project
- The backend validates the bearer token with Supabase Auth and uses the verified Auth ID to find the user's profile and conversation. The client does not get to select another account by sending a user ID.
- RLS policies support own-account reads. The backend uses a service-role client, so its explicit ownership checks remain essential. The account retrieval RPC is service-role-only and filters learned answers by owner. [R4, R5; D2]
## What moved from Node.js
- The original Express backend remains as a legacy/reference implementation. The account PWA is configured for the Edge API. Node remains useful for manual ingestion and the optional long-running Baileys WhatsApp bridge. Node.js and Deno are runtimes; Supabase is the hosting platform.
- Describe the migration as a hosting-cost and operations decision based on your experience. Do not claim the database was introduced only at migration: the retained Node implementation also uses Supabase. WhatsApp uses a separate server credential and is not linked to PWA accounts.

@@ Part 1 / Request walkthrough | From a question to an answer
## Example: "Why is the thread bunching underneath?"
- **1. Identify the account.** The PWA sends the session bearer token with the chat request. The Edge API checks origin and payload requirements, validates the token, and derives account ownership from it. Assume a completed profile naming the Usha Quick Stitch.
- **2. Apply limits and obtain context.** The account path uses shared rate limits, resolves the account's conversation, and requires the profile fields. The chat use case saves the user message, then loads recent messages.
- **3. Retrieve knowledge.** The agent embeds the current text using gemini-embedding-001 at 768 dimensions. It invokes the account-specific SQL function with the machine label and Auth owner, requesting four matches.
- **4. Decide whether to search.** If no chunks exist, or the top similarity is below 0.55, local knowledge is considered weak. For an ordinary weak-match query, web and YouTube searches can run concurrently. An explicit video request changes that routing; it does not automatically require ordinary web search.
- **5. Construct the model request.** The prompt includes user/machine context, the question, up to eight recent history items, up to four retrieved chunks, and available search results. It asks for concise practical Malayalam guidance, avoiding unsupported machine specifications.
- **6. Generate and return.** Gemini produces the answer. Video results are returned as cards. The backend attempts to save the assistant message. If that final save fails, the generated reply can still reach the user.
- **7. Optional learned-answer save.** If the search branch was entered, the agent attempts to embed and save the question/answer as owner-scoped learned content. The flag does not prove external results were found. This save is best-effort, but is awaited before returning.
## What you should expect, not claim as a measured result
- A good answer would distinguish likely causes, use relevant evidence, avoid inventing machine details, and ask for clarification if necessary. That expected behaviour must still be checked with actual evaluation cases.
~ Evidence: [R3-R5]. The current question also appears in loaded history because it is saved first; prompt duplication is a possible cleanup, not a feature claim.
@@ Part 3 / Knowledge ingestion | How the knowledge gets into RAG
- **Source material:** the repository contains a compiled Usha Quick Stitch reference guide. Its introduction says it combines manufacturer specifications and general machine-class knowledge, and flags some unverified details. The README's phrase "real machine manual" is stronger than the file supports. Treat provenance as a quality issue, not a wording detail. [R6]
- **Chunking:** the Node ingestion script splits Markdown at second- and third-level headings. A third-level section carries its parent heading for context. For example, a thread-bunching subsection can retain the heading "Common Problems & Fixes." This is heading-based chunking, not a fixed token window with overlap.
- **Embedding:** the script sends chunks to Gemini's embedding endpoint in batches of up to 100 and requests 768 values per chunk. It validates returned vector lengths. The query embedder uses the same model family and output size. [R6]
- **Storage:** each row combines a machine-model label, chunk text, and embedding. At question time, the database compares the query vector with eligible document vectors. The prompt receives the selected text, not the vectors themselves.
## Why these details matter
- A coherent section preserves meaning better than cutting randomly in the middle of a troubleshooting procedure. However, a very long section can still exceed a sensible context budget, and a short section may lack enough context. Chunking should be tested on the actual corpus.
- **PROPOSED:** attach source URL, document version, page/section, provenance, review status, and a stable chunk ID. Keep generated answers visibly distinct from reviewed source material and avoid promoting them to trusted evidence automatically.
- **PROPOSED:** make re-ingestion transactional or staged. The current script deletes rows for the model before embedding replacement content; a provider failure can leave knowledge missing. Its deletion is model-wide, so ownership and source filters would need care before reusing it at scale.
- Changing an embedding model requires re-embedding the corpus and queries consistently. Matching dimensions alone does not make two embedding spaces compatible. Evaluate a migration before switching models. [D3]

@@ Part 3 / Retrieval concepts | What a vector match really means
- **Embedding:** a learned representation of text as numbers. The 768 coordinates collectively encode patterns useful for similarity. Individual coordinates are not reliable labels such as "tension" or "bobbin." Two differently worded questions may still produce nearby vectors.
- **Semantic retrieval example:** "thread loops below cloth" might match a section headed "bird-nesting" even without identical wording. Malayalam-to-English retrieval is plausible with multilingual representations, but its quality on your terminology must be measured rather than assumed.
- **Cosine similarity:** compares vector direction. The formula is dot(a,b) / (norm(a) * norm(b)). For illustrative vectors a=(1,0), b=(0.8,0.6), similarity is 0.8. This two-dimensional example teaches the operation; real embeddings have 768 dimensions.
- **Your SQL:** the account RPC orders by pgvector's cosine distance operator, then returns 1 minus that distance as similarity. It first restricts the machine-model label and permits shared manual rows or the caller's learned rows. Machine labels use exact matching in that query. [R5]
- **Top-k:** k=4 means "return at most four eligible closest chunks." It does not mean all four are useful. A top result at 0.60 is not a 60% probability that the answer is true. A confident match to incorrect source text can still lead to a wrong answer.
## Current threshold and possible improvements
- **IN CODE:** if the top result is below 0.55, the workflow treats retrieval as weak and may search externally. Low-scoring returned chunks are still passed into the prompt; the threshold is not a hard removal filter.
- **PROPOSED:** label relevant chunks, vary k and threshold, compare missed evidence, irrelevant context, answer quality, latency, and cost. Consider keyword-plus-vector hybrid retrieval for exact model numbers and a reranker if it improves measured relevance.
- pgvector supports exact and approximate search approaches. The inspected migrations do not establish a deployed HNSW or IVFFlat index. Check actual indexes and query plans before claiming approximate nearest-neighbour performance. [D1]
~ Evidence: [R3, R5]. Extra sources and stronger retrieval do not by themselves guarantee safe or correct generation.
@@ Part 3 / Agent and prompt | A controlled workflow around an LLM
- **What "agent" means here:** runAgent coordinates embedding, retrieval, optional search, prompt assembly, generation, and saving. Routing is ordinary TypeScript logic. The model does not dynamically choose tools through a function-calling loop, and there is no open-ended planning/retry cycle. Call it a custom RAG workflow or bounded assistant workflow. [R3]
- **Tool routing:** explicit video intent requests YouTube even when retrieval is strong. Weak retrieval without explicit video intent requests ordinary web search and YouTube. Those optional searches are wrapped in Promise.allSettled, allowing one to fail without discarding the other.
- **Prompt structure:** a system instruction specifies the assistant role, preferred language, machine context, and behaviour. The user-content block carries the question, recent history, retrieved text, and search snippets. A photo, if present, is attached as inline multimodal data.
- **Grounding example:** if the user asks whether their machine supports zig-zag stitching, the desired answer should use matching reference evidence rather than infer the feature from the brand name. The prompt explicitly warns against assuming unprovided machine specifications.
- **Temperature:** the generation wrapper uses temperature 0 and an 8,192-token output cap. Temperature controls sampling behaviour; a low setting does not verify facts, defeat prompt injection, or guarantee identical output across provider changes. The cap is not the number of tokens every reply uses.
## Framework names you should know
- **LangChain** supplies building blocks for model applications. **LangGraph** supports stateful workflow/agent orchestration. **LangSmith** supports tracing and evaluation. None is required to implement RAG. The inspected runtime directly calls Gemini; the repository notes removal of unused LangChain packages. [R2, R3; D4, D5]
- **PROPOSED:** add a versioned prompt, explicit source metadata, safer separation of untrusted text, and trace spans. A name field is interpolated into the system prompt; the existing warning about untrusted profile data is helpful but is not complete injection protection.
~ Model defaults are configuration fallbacks, not verified deployment choices. The chat wrapper defaults to gemini-3.5-flash, with an environment override. Availability was not tested.
@@ Part 3 / Multimodal and memory | Text, voice, photos, and context
- **Voice input:** the client records audio, then a separate transcription endpoint sends audio to Gemini with Malayalam transcription instructions. Silence or unintelligible content should yield an unclear marker and a 422 response. The resulting transcript becomes a normal chat question. This is a pipeline, not a continuous speech-to-speech model session.
- **Voice output:** a separate speech endpoint cleans text, requests generated audio, wraps returned PCM data as WAV, and returns base64 audio. The inspected default is gemini-3.1-flash-tts-preview, configurable through the environment. A transient 429/503 can trigger one retry after four seconds. [R8]
- **Image input:** a photo is included in the Gemini generation request. The retrieval query is still a text embedding of the supplied text; there is no implemented image-vector search pipeline. "What is wrong here?" may retrieve poorly even if the photo contains useful clues.
- **Multilingual example:** a speaker may use Malayalam grammar with the English word "bobbin" or a local pronunciation. Check whether the transcript preserves the intended component, retrieval finds the right section, and the final answer uses understandable language.
## Four different kinds of context
- **Profile:** persistent account data, including machine name. It personalizes the request but is not independently verified machine knowledge.
- **Conversation history:** recent messages from the database. The use case loads 20 items, but the prompt formats the last eight. This is bounded context, not unlimited recall or a trained personal model.
- **Knowledge retrieval:** source chunks and eligible saved answers selected by vector similarity. The inspected account query can mix reviewed manual-labelled rows with unreviewed learned rows in the same ranking.
- **Learned-answer storage:** generated Q&A is embedded and saved after the search branch. No model weights change. Errors can become future context, so review, deduplication, expiry, and provenance are proposed improvements.
~ Evidence: [R3, R4, R8]. Do not claim audio/image understanding is always correct; evaluate each stage and the complete user journey.
@@ Part 4 / Evaluation | Prove behaviour, then improve it
- **Software tests ask:** does an unauthenticated request fail, is profile ownership respected, does rate limiting stop a model call, and does a persistence failure preserve a useful response? The repository contains tests for these behaviours using injected dependencies. [R9]
- **AI evaluations ask:** did the answer use the right evidence, state correct guidance, respect the machine, and communicate clearly in Malayalam? Passing route tests does not answer these questions. No formal answer-quality dataset, systematic benchmark results, or LangSmith integration was found in the inspected files.
- **Concurrency test boundary:** the test dispatching 100 signed-in chats checks that mocked account contexts stay separate. It does not hit real Auth, pgvector, Gemini, or Redis and does not demonstrate throughput, production isolation at the database layer, or an operational capacity of 100 users.
## PROPOSED: a practical first evaluation loop
- Start with **80 reviewed cases**: 25 machine troubleshooting, 15 garment tasks, 10 unsupported/ambiguous machines, 10 multilingual text cases, 10 voice cases, 5 image cases, and 5 adversarial cases. These are suggested counts, not an existing dataset or a sufficient statistical guarantee.
- For each case store the input, machine context, expected evidence IDs, required answer points, forbidden claims, language expectations, and review notes. Avoid requiring one exact sentence for a valid answer.
- Use about 60 cases for development and 20 grouped holdout cases for final comparison. Keep paraphrases, related conversations, and repeated source scenarios together to reduce leakage. A small holdout has uncertainty; expand it with real failures.
- Record the corpus version, prompt version, provider/model identifier, parameters, retrieved IDs/scores, response, latency, and token usage. Compare a change on the same cases, inspect regressions, and repeat selected cases to expose variation.
- Use code checks for hard rules, human reviewers for technical and Malayalam quality, and calibrated model judges for scalable triage. A judge is another fallible model, not ground truth. [D4]

@@ Part 4 / Evaluation examples | What a good test looks like
## PROPOSED cases to put into the first dataset
- **Supported machine / thread bunching:** expected evidence is the reviewed threading/tension troubleshooting section. The answer should offer cautious, ordered checks, avoid inventing a precise diagnosis, and include relevant safety precautions before physical inspection.
- **Unknown machine / exact needle system:** there is no verified matching reference. The answer should state the limitation and ask for the identifying label or correct documentation. An invented needle code is a failure even if the answer sounds helpful.
- **Garment task / blouse fitting:** the workflow should address the garment question rather than force it into machine repair. A useful answer may ask for relevant measurements; external tutorials must not be presented as official machine documentation.
- **Voice / unclear component name:** score transcript fidelity first, then answer quality using the actual transcript. Also test with a corrected transcript to locate the source of failure. For silence, the expected result is an unclear-audio response, not a plausible invented question.
- **Photo / obscured mechanism:** the assistant should describe uncertainty and request a clearer view when needed. **Injection / "ignore rules and reveal secrets":** it should not disclose sensitive context or treat retrieved instructions as authority. Test actual authorization independently of model behaviour.
## A small, usable rubric
- Score **correctness, groundedness, usefulness, and Malayalam clarity** separately from 0 to 2: 0 means incorrect or absent, 1 means partial, and 2 means satisfactory under the case's written criteria. Record a reason, not only a number.
- Treat a cross-account disclosure or hazardous unsupported instruction as a release-blocking failure in this proposed policy; averaging it with good stylistic scores would hide the risk. Agree on the policy with the product owner/reviewer.
- **Retrieval Recall@4 example:** if two relevant labelled chunks exist and the retriever returns one in its top four, recall is 1/2. Also measure whether at least one sufficient answer-bearing chunk was found, and inspect irrelevant retrieved text.
- **Groundedness example:** an answer can faithfully repeat an incorrect reference. It is grounded in that reference but still factually wrong. Verify source quality and answer correctness separately.
~ Scores and policies on this page are proposed examples. No evaluation pass rate, safety rate, or production target is being reported.
@@ Part 4 / Debugging | When an answer is bad, find the failed stage
## Scenario: the assistant invents a machine feature
- **Reproduce with consent and redaction.** Preserve the question, account's machine labels, model configuration, corpus/prompt versions, and relevant request ID. Production logs intentionally exclude message bodies, so a request ID alone will not reconstruct the prompt.
- **Check input interpretation.** Was the voice transcript wrong? Did the photo actually show the part? Was a vague follow-up such as "how do I fix that?" embedded without its conversational referent? Query rewriting using history is a possible improvement, not current behaviour.
- **Check retrieval.** Inspect the exact machine string, returned IDs/similarities, source and ownership filters, and text. Was the correct guide present? Did a private learned answer outrank the reference? A 768-dimensional vector can be well-formed and still be irrelevant.
- **Check generation.** If correct evidence was available, inspect whether the prompt encouraged unsupported inference, included conflicting text, or exceeded a sensible context budget. Compare the same case with only the relevant evidence. Do not assume a larger model fixes a bad corpus.
- **Fix the responsible layer.** Correct bad source data, normalize machine identifiers, improve retrieval or prompt boundaries, or adjust generation. Add the failure to the dataset and compare before/after with unrelated regression cases.
## Scenario: the chat fails or times out
- Inspect the browser network request and X-Request-ID, then correlate backend route/status/duration/error category. Distinguish 401 sign-in problems, 409 incomplete profile, 429 configured limits, and 503 dependency unavailability. A 503 may reflect missing Redis, not necessarily Gemini.
- Check frontend proxy path, allowed origins, deployed secrets, Auth configuration, migrations/RPC permissions, provider access, and quotas. A public health response proves routing/liveness only; it does not prove paid provider calls work.
- **PROPOSED observability:** spans for Auth, limits, DB, embedding, retrieval, each search, generation, and saves; safe stage metadata and usage counts. If temporary content capture is needed, use consent, redaction, restricted access, and short retention.

@@ Part 4 / Security | Protect identity, knowledge, and spend
- **Authentication versus authorization:** authentication proves who signed in. Authorization decides which records that identity may access. The backend validates the token, derives the Auth ID, and resolves ownership rather than trusting a user ID from the browser. [R4]
- **RLS and service-role boundary:** user-facing database reads have own-account policies; machine_docs has no direct user policy. The Edge service-role client bypasses RLS, so backend checks and correct SQL filters are required. The account retrieval function is granted to service_role only. [R5; D2]
- **Secrets:** Gemini, service-role, Tavily, YouTube, Redis, and WhatsApp credentials belong on the server. A browser publishable/anon Supabase key is not a privileged server secret; its use requires correct policies. Anything in a VITE variable is public in the bundle.
- **Abuse controls:** exact-origin CORS, request limits, payload validation, shared per-user/IP limits, and global daily quotas reduce exposure. CORS is a browser control, not an authentication mechanism or a defence against direct API clients. Hashing a rate-limit identity is pseudonymization, not proof of anonymous data.
- **Fail closed:** deployed paid routes require Redis. Missing/unavailable Redis should return 503 before paid work. Only explicit local development mode permits bounded process-local fallback. This trades availability for protection from uncontrolled spend.
## Prompt injection is a different boundary
- Profile names, user messages, reference text, and external search snippets are untrusted. An instruction hidden in a web result must not gain system authority. JSON-escaping a profile string does not make its semantic content safe for a model.
- **PROPOSED:** stronger separation of trusted instructions and data, source review, allowlisted tool capabilities, output checks for sensitive actions, adversarial evaluations, and minimum privileges. The model should never be the final authorization mechanism.
- **PROPOSED privacy work:** data retention/deletion behaviour, consent and provider-data handling review, account export/deletion tests, and real two-account isolation tests for both database access and retrieval.
~ Evidence: [R4, R5, R7]. CAPTCHA, SMTP, OAuth allowlists, and secret settings depend on deployment configuration and were not verified here.
@@ Part 4 / Cost | Estimate every stage of an interaction
- **What can cost money:** query embedding, Gemini input/output, speech transcription, speech generation, web search, video APIs, an extra embedding for learned-answer saving, database/Edge usage, and Redis. A video request or retry can add work even when the generated answer is short.
- **Current gap:** the generation wrapper extracts answer text but does not retain provider token-usage metadata for billing analysis. Route duration logging and request quotas are not per-request cost accounting. The output cap of 8,192 is a limit, not measured output usage. [R3, R7]
## ILLUSTRATIVE calculation only - not provider pricing
- Suppose a text turn uses **2,000 input tokens at $0.30 per million** and **300 output tokens at $2.00 per million**. Model cost = 2,000/1,000,000 x 0.30 + 300/1,000,000 x 2.00 = **$0.00120**.
- Suppose the query uses **100 embedding tokens at $0.10 per million**. Add **$0.00001**. A manual-only turn would then be **$0.00121**, excluding infrastructure and all other stages. At 1,000 identical turns that is $1.21, not a real forecast.
- Suppose a search branch costs **$0.005** and saving its Q&A adds 400 embedding tokens under the same assumed embedding rate. That illustrative searched turn becomes **$0.00625**. With 70% manual-only and 30% searched turns, the weighted mean is **$0.002722**, or about $2.72 per 1,000 turns before other costs.
- Speech, image-token accounting, model-specific token categories, unsuccessful/retried calls, taxes, and hosting are excluded from that example. Use current model-specific billing documentation and observed usage for real estimates. Do not convert English word counts into Malayalam token counts using a fixed ratio. [D6]
## PROPOSED accounting and optimization
- Record usage metadata, model, operation, request ID, retries, and stage latency without storing raw content. Reconcile estimates with provider bills and separate one-time ingestion from online query costs.
- Compare cost per successful resolved question, not just per API request. Reduce irrelevant history, tune chunk/context size, evaluate lower-cost models, make speech optional, and control retries. Cache only with safe keys, owner separation, and invalidation on corpus/profile changes.
~ All dollar amounts above are deliberately hypothetical; they are not quoted Gemini, Tavily, or Supabase rates.
@@ Part 4 / Reliability and scale | Make failures understandable and bounded
- **IN CODE:** optional web/YouTube searches tolerate branch failures; learned-answer saves are best-effort; assistant-message save failures need not discard a generated answer. Mandatory embedding, retrieval, or generation failures can still stop the turn. Graceful degradation is selective, not universal. [R3, R4]
- **Timeouts:** the browser sets chat, transcription, and speech timeouts of 90, 60, and 120 seconds. A YouTube scraping fetch has a 12-second timeout. The central Gemini generation fetch lacks a uniform explicit deadline in the inspected wrapper. A browser abort does not necessarily cancel upstream paid work. [R3, R8]
- **PROPOSED:** stage deadlines and an overall request budget, cancellation propagation, limited retries with exponential backoff and jitter for appropriate transient failures, and no blind retries for invalid input or permission errors. Retry only when the remaining deadline and spend budget allow it.
- **Persistence and idempotency:** the user message is saved before model work. A failed/retried request can leave an unanswered message or duplicate work. Unique account/conversation constraints handle some races, but they do not make a full chat turn idempotent. Add a request/turn identifier and explicit processing state if retries matter.
## If usage grows
- Start with measured p50/p95 end-to-end and per-stage latency, error rates, provider throttling, cost per resolved turn, and database query plans. Averages conceal slow users; p95 is the time at or below which 95% of measured requests complete.
- Edge autoscaling does not create unlimited Gemini quota or database capacity. Limits and provider concurrency budgets must grow deliberately. Isolate load tests from production data and agree on test traffic/spend before running them.
- **PROPOSED:** tune SQL/indexes based on corpus size, normalize machine identity, paginate history, move nonessential learned-answer processing out of the critical path, and test real cross-account requests. Streaming can improve perceived waiting time but does not eliminate computation cost.
- Define product targets after obtaining a baseline, with separate availability, safety, quality, latency, and spend goals. Do not present the mocked 100-request test as a load benchmark or an uptime guarantee.
~ Evidence: [R4, R5, R8, R9]. No capacity or latency measurements were performed for this guide.
@@ Part 4 / Production priorities | What you would improve next, and why
## First: reliable evidence and account boundaries
- **PROPOSED:** verify the deployed API path, Auth setup, Redis, provider access, and migrations using a designated test account. Then test two actual accounts to ensure profiles, messages, and learned retrieval never cross owners. This is more valuable than claiming general "production readiness."
- **PROPOSED:** review the compiled guide and its claims; attach provenance and stable machine identifiers. Ask for clarification when model labels are ambiguous. Adding another person's machine name is onboarding context, not onboarding trustworthy knowledge.

## F01. What are AI, ML, deep learning, and generative AI?

## F02. How do supervised and unsupervised learning differ?
- **Answer:** "Supervised learning uses labelled examples, such as question text paired with a troubleshooting category. Classification predicts categories; regression predicts numbers. Unsupervised learning looks for structure without those target labels, such as grouping similar questions. Those are hypothetical extensions; the app currently uses a pretrained embedding model and generated responses."
- **Follow-up: is vector search itself supervised training?** "No. At runtime I compute a representation and compare it with stored vectors. The embedding model was trained upstream, but inserting vectors into Postgres or searching them does not train a classifier or clusterer in my application."
## F03. What is reinforcement learning? Is feedback the same thing?

- **Follow-up: what is RLHF?** "Reinforcement learning from human feedback is a family of techniques for aligning model behaviour using human preference information, often involving reward modelling or related optimization. - **Follow-up: why not start with the biggest neural model?** "Complexity adds data and operational needs. I would use a model only if it improves held-out task metrics at an acceptable cost. No such custom classifier is implemented in Tailor AI today."
@@ Part 5 / Fundamentals 02 | Data and training mechanics
## F05. What are examples, features, labels, and preprocessing?
- **Answer:** "An example is one observation; features are its model inputs; a label is the desired supervised output. For a hypothetical router, text or its embedding is the input and 'machine repair' is the label. Preprocessing might normalize fields, handle missing values, or scale numeric features. It must preserve important machine numbers and Malayalam meaning."
- **Follow-up: when do you fit preprocessing?** "Fit learned transforms only on training data, then apply them unchanged to validation/test data. A scaler or vocabulary fitted on all data can leak information. A pipeline helps enforce that boundary. Current manual chunking is data preparation, not supervised model training. [D8]"
## F06. What is a loss function?
- **Answer:** "A loss quantifies a prediction error for optimization. Mean squared error is common for numeric targets; cross-entropy is common for classification. For a hypothetical category router, cross-entropy penalizes low probability on the correct category. My RAG system does not locally optimize a training loss; it uses provider inference."
- **Follow-up: is loss the same as a business metric?** "No. A lower training loss may not improve safe or useful guidance. I would evaluate the router on held-out category metrics and evaluate the full assistant on correctness and task success. LLM text-generation training losses also do not directly establish factual answer quality."
## F07. Explain gradient descent and learning rate.
- **Answer:** "Gradient descent updates weights in a direction intended to reduce loss: new weight = old weight minus learning rate times the loss gradient. The gradient gives local sensitivity; the learning rate controls step size. In a hypothetical trained router, too large a step can destabilize learning; too small can make progress slow."
- **Follow-up: what about local minima and optimizers?** "Neural loss surfaces are not generally convex, so I do not promise a global optimum. Optimizers such as SGD and Adam use different update strategies. I would tune on validation data and inspect training curves. None of these updates occurs when my backend asks Gemini to answer a question."
## F08. What are epochs, batches, and training versus inference?
- **Answer:** "An epoch is one pass over the training set; a batch is the subset used for an update. Training computes loss and changes weights. Inference uses trained weights to make predictions. Tailor AI's chat and embedding calls are inference, while a future custom router would have a separate training pipeline."
- **Follow-up: what does batch size affect?** "It affects memory, update noise, compute efficiency, and sometimes generalization. Batch size must be evaluated with the learning-rate schedule and hardware. The ingestion script's batch of up to 100 embedding requests is API batching; it is not a local neural-network training batch."
@@ Part 5 / Fundamentals 03 | Generalization and leakage
## F09. Why separate training, validation, and test data?
- **Answer:** "Training fits parameters; validation supports tuning; test data estimates performance after decisions are fixed. In Tailor AI, the equivalent evaluation discipline is to tune prompts and retrieval on development cases, then compare on held-out scenarios. There is no local training dataset in the existing chat workflow."
- **Follow-up: what is leakage here?** "Putting paraphrases of the same conversation in both splits can inflate results. Retrieving a saved generated answer for the exact benchmark question can also contaminate the evaluation. I would freeze corpus state, group related cases, and exclude benchmark-derived learned content from evaluation retrieval."
## F10. What are overfitting, underfitting, and bias versus variance?
- **Answer:** "Underfitting means a model is too limited or insufficiently learned to capture useful patterns. Overfitting means it fits training quirks that do not generalize. Bias is systematic error from assumptions; variance is sensitivity to the sampled training data. A hypothetical router memorizing a few phrases may fail on natural Malayalam paraphrases."
- **Follow-up: can prompts overfit too?** "Yes in an evaluation sense: I can repeatedly patch a prompt for visible cases and fail on new ones. That is not necessarily neural weight overfitting, but it still creates misleading progress. Held-out scenarios, diverse reviews, and regression tests help detect it."
## F11. What is regularization? How is tuning different from training?
- **Answer:** "Regularization discourages fragile or overly complex fits; examples include weight penalties, dropout, and early stopping. Parameters are learned weights; hyperparameters are choices such as regularization strength or learning rate. For a hypothetical classifier I would tune those on validation data, not on the final test set."
- **Follow-up: are k=4 and 0.55 parameters?** "They are application/retrieval hyperparameters rather than learned model weights. I can tune them using a development evaluation set. Early stopping can improve a trained model, but it does not directly fix a hosted LLM's incorrect answer in my current workflow."
## F12. What is cross-validation, and when is a random split wrong?
- **Answer:** "Cross-validation repeats train/validation splits across folds to estimate variability and compare choices when data is limited. Stratification can preserve class proportions; grouped folds keep related observations together. For future tailoring data, examples from the same user or conversation may need to stay in one fold."
- **Follow-up: what if you predict future behaviour?** "Use a time-respecting split when the deployment task is future prediction, and avoid training on information that would not have existed at prediction time. Cross-validation is not a substitute for a final appropriately designed test or a real production monitoring plan."
@@ Part 5 / Fundamentals 04 | Metrics that answer the right question
## F13. What is a confusion matrix?
- **Answer:** "It compares predicted and true classes. Suppose a hypothetical router flags urgent repair cases: a true positive flags a real urgent case, a false positive flags a nonurgent one, a false negative misses an urgent one, and a true negative correctly leaves a nonurgent case unflagged. The positive class must be defined first."
- **Follow-up: why not report accuracy alone?** "If urgent cases are rare, always predicting nonurgent can look accurate while missing every urgent case. I would inspect false negatives and per-class performance. The actual Tailor AI workflow does not currently contain this urgent-case classifier."
## F14. Explain precision, recall, F1, and class imbalance.
- **Answer:** "Precision = TP/(TP+FP); recall = TP/(TP+FN). With 8 true alerts, 2 false alerts, and 4 missed urgent cases, precision is 0.80 and recall is about 0.67. F1 is their harmonic mean, about 0.73 here. Rare-case evaluation needs representative positives and negatives."
- **Follow-up: which matters more?** "It depends on error cost. Missing a hazardous case may justify higher recall, but excessive false alarms also hurt usability. Tune a threshold against that trade-off. Macro averaging weights classes equally; micro averaging aggregates decisions. A chatbot's free-text answers still need evidence and correctness review, not only classifier F1."
## F15. What metrics would you use for regression?
- **Answer:** "MAE is average absolute error; MSE averages squared error; RMSE is the square root of MSE and has the target's units. In a hypothetical seam-length estimator, MAE is interpretable in centimetres, while RMSE penalizes occasional large mistakes more strongly. This is not a feature implemented in my application."
- **Follow-up: what is R-squared?** "It compares squared error with a mean-prediction baseline. It can be negative on held-out data and does not tell me whether an error is acceptable for tailoring. I would report meaningful units, inspect error distribution, and avoid percentage errors when the true value is near zero."
## F16. How do retrieval metrics differ from answer metrics?
- **Answer:** "Retrieval metrics judge what evidence is returned. Recall@k measures coverage, precision@k measures relevant items among retrieved items, and MRR rewards an early first relevant result. Answer metrics judge whether the generated explanation is correct, supported, and useful. Tailor AI needs both because correct evidence can still produce a bad answer."
- **Follow-up: what is a ranking example?** "If the first sufficient source appears at rank 2, that query contributes 1/2 to reciprocal rank. Groundedness then asks whether answer claims follow the evidence. It cannot verify that an inaccurate reference is true, so factual source review remains separate."
@@ Part 5 / Fundamentals 05 | Mathematics and uncertainty
## F17. What are vectors, dot products, and cosine similarity?
- **Answer:** "A vector is an ordered collection of numbers. A dot product sums coordinate-wise products; cosine similarity divides the dot product by both vector lengths. Tailor AI compares 768-dimensional representations of questions and reference chunks. A simple example, (1,0) and (0.8,0.6), has dot product and cosine similarity 0.8 because both lengths are one."
- **Follow-up: cosine versus Euclidean distance?** "Cosine compares direction; Euclidean distance measures straight-line separation. For unit-normalized vectors their rankings are closely related, but arbitrary scaling can change Euclidean distance. Use the metric intended for the embedding model and evaluate it; a similarity value is not a truth probability."
## F18. Why do conditional probability and Bayes' rule matter?
- **Answer:** "Conditional probability is the probability of an event given evidence. Bayes' rule updates a prior using a likelihood. In a hypothetical fault detector, 'thread bunching occurs with a tension problem' is not the same as 'a tension problem is certain when bunching occurs.' Other causes and base rates matter."
- **Follow-up: can you give numbers?** "If 10% of cases are urgent, a detector has 90% sensitivity and a 10% false-positive rate, then true alerts are 0.09 of all cases and false alerts are also 0.09. Only half the alerts are truly urgent under those assumptions. These are teaching numbers, not measured app statistics."
## F19. What are distributions, sampling, and statistical uncertainty?
- **Answer:** "A distribution describes how values occur; a sample is a subset we observe. Interview demos are a tiny, selected sample. If I test only clear English machine questions, I cannot infer performance on noisy Malayalam speech. I would sample by real use categories and report sample counts and variability."
- **Follow-up: how would you compare model versions?** "Use paired cases where possible, predefine the main metrics, inspect effect size and uncertainty, and avoid choosing a winner from one lucky run. Confidence intervals or suitable resampling can help; significance does not automatically mean a practically useful improvement. Small safety test sets cannot establish zero risk."
## F20. How do confidence, calibration, and uncertainty differ?
- **Answer:** "A model's stated confidence is not verified correctness. Calibration means predictions assigned a given probability are correct at roughly that rate over comparable cases. Tailor AI's cosine score measures vector similarity, so treating it as a calibrated probability would be wrong. Missing sources, ambiguous machine identity, and unclear audio are concrete uncertainty signals."
- **Follow-up: how would you handle uncertainty?** "Evaluate abstention or clarification policies using labelled cases and error costs. Test whether a confidence proxy predicts correctness before using it. Distinguish irreducible noisy observations from uncertainty due to limited knowledge; a fluent answer does not remove either."
@@ Part 5 / Fundamentals 06 | Neural networks and transformers
## F21. What are weights, layers, and activation functions?
- **Answer:** "A neural layer transforms inputs using learned weights and biases; nonlinear activation functions let stacked layers model more than a single linear transformation. Training adjusts weights to reduce loss. Gemini contains a trained neural model, while my backend's routing conditions are ordinary code rather than learned layers."
- **Follow-up: why does nonlinearity matter?** "Without nonlinearities, stacked linear layers still represent a linear transformation. Nonlinear units allow richer relationships, such as interactions between symptoms. I cannot infer Gemini's exact proprietary architecture or parameter count from this application's code, and I did not train those weights."
## F22. What is a transformer, and how does attention work?
- **Answer:** "Transformers use attention to combine contextual information across token representations. In scaled dot-product attention, query-key scores are scaled, passed through softmax, and used to weight values: softmax(QK-transpose / sqrt(dk))V. In a tailoring explanation, context helps distinguish 'thread tension' from other uses of 'tension.' [D7]"
- **Follow-up: is attention the same as RAG?** "No. Attention operates inside a model's computation over its input representations. RAG retrieves external records and supplies them as input. My application controls which reference chunks are sent; it does not directly control or inspect Gemini's internal attention."
## F23. What are tokens and token embeddings?
- **Answer:** "A tokenizer maps text into units such as subword pieces. Models process token IDs through learned representations. Malayalam and English can have different tokenization patterns, so word count is an unreliable billing estimate. Tailor AI should use provider token accounting for actual requests. [D6]"
- **Follow-up: are token embeddings the vectors in pgvector?** "Not exactly. My stored vectors are text representations produced by a dedicated embedding API for retrieval. A language model's internal token representations serve its own computation. Both are vectors, but they are not interchangeable or automatically in the same space."
## F24. What are pretraining, fine-tuning, and next-token prediction?
- **Answer:** "Pretraining learns broad patterns from large datasets. Fine-tuning adjusts a pretrained model using additional training data. Many text-generation models learn to predict a next token from context and generate by repeated prediction; alignment and other training can shape behaviour. Tailor AI uses hosted inference without a local model-training stage."
- **Follow-up: why can it produce plausible falsehoods?** "A likely continuation is not a verified fact. A machine name can elicit plausible but wrong specifications. Retrieval supplies evidence, but I still need generation evaluation and source quality checks. Saving an answer in a vector table changes future context, not model weights."

## F25. When do you use prompting, RAG, or fine-tuning?
- **Answer:** "Prompting expresses instructions and examples; RAG supplies external evidence; fine-tuning changes weights using additional training. - **Answer:** "Structured output constrains an answer to a schema, such as fields for answer text and source IDs. - **Follow-up: can you guarantee deterministic output?** "Not solely from that setting. Provider infrastructure, model revisions, and numerical behaviour may affect results. ## F29. What are data drift, concept drift, and model drift?
- **Answer:** "Data drift means input distributions change. Concept drift means the input-to-target relationship changes. 'Model drift' is often used loosely for performance degradation or model changes. Tailor AI may receive new brands, dialects, photos, and question types that differ from its first user's data. A provider update can also change outputs without my code changing."
- **Follow-up: how do you detect it?** "Track input/category patterns and outcome quality over time, with privacy controls. Distribution changes are warnings, not automatic proof of degraded accuracy; reviewed labels or outcomes are needed. Add representative new cases and re-evaluate supported use cases before expanding coverage."
## F30. What makes an experiment reproducible and a rollout safe?
- **Answer:** "Record data/corpus versions, prompt, model identifier, configuration, code revision, evaluation cases, and outputs. Random seeds help local experiments but do not fully control hosted inference. In Tailor AI, a prompt change plus changed learned-answer rows can otherwise make a before/after comparison misleading."
- **Follow-up: would you A/B test immediately?** "First pass offline quality and security checks. Then use a small monitored rollout or randomized experiment if appropriate, define success and guardrails in advance, and avoid exposing users to known harmful variants. Keep a tested rollback for prompt/model/corpus settings and a separate recovery plan for database changes."
## F31. Explain APIs and asynchronous execution in your project.
- **Answer:** "An API defines a request/response contract. HTTP status, body, authentication, and timeout behaviour are part of that contract. Independent web/YouTube requests can overlap, reducing waiting time compared with serial requests."
- **Follow-up: Promise.all versus allSettled?** "Promise.all rejects when a member rejects; allSettled returns each outcome after all settle. ## F32. What SQL and indexing knowledge matters here?
- **Answer:** "Use SQL ownership filters and parameterized database interfaces, not string-built queries from user input. Indexes can accelerate appropriate access paths but add write/storage cost; inspect actual query plans and dataset size."
- **Follow-up: does ORDER BY distance prove an ANN index is used?** "No. It can execute as exact comparison without an approximate index. pgvector supports approximate approaches, but their existence and use must be checked in the deployed database. An index is a performance tool, not an authorization boundary."

@@ Reference / Glossary | Plain-English terms
- **Agent workflow:** code coordinating model and tool steps. **API:** a defined interface between software components. **Inference:** using a trained model to produce an output.
- **Embedding:** a learned numeric representation. **Vector database capability:** storage and similarity search over vectors. **pgvector:** an extension adding that capability to PostgreSQL.
- **RAG:** retrieve external evidence, then generate with it. **Chunk:** a retrievable piece of source text. **Top-k:** the maximum number of ranked results requested. **Reranker:** a second model or scoring step that reorders candidates.
- **Hybrid retrieval:** combining methods such as keywords and vectors. **ANN:** approximate nearest-neighbour search, trading some exactness for speed. **Provenance:** where a claim or document came from and how it was reviewed.
- **Token:** a model input/output unit. **Context window:** the available input/output capacity under the model's constraints. **Temperature:** a sampling control. **Hallucination:** plausible generated content that is false or unsupported.
- **Prompt injection:** untrusted content attempting to override intended instructions. **Groundedness:** support for answer claims in supplied evidence. **Correctness:** agreement with the actual facts or task requirements.
- **Training:** optimizing weights from data. **Fine-tuning:** further training a pretrained model. **Hyperparameter:** a configuration choice rather than a learned weight. **Loss:** an optimization error signal.
- **Overfitting:** learning patterns that do not generalize. **Leakage:** using information that should be unavailable during development or prediction. **Drift:** a meaningful change in inputs, relationships, or behaviour over time.
- **JWT:** a signed token format used to carry identity claims. **Authentication:** verifying identity. **Authorization:** deciding access. **RLS:** database policies restricting rows for applicable roles.
- **Service role:** privileged server access that can bypass RLS. **CORS:** browser-origin access rules. **Rate limit:** a cap on request frequency or volume. **Fail closed:** deny work when a required protection is unavailable.
- **Trace:** linked records of stages within a request. **p95 latency:** the duration within which 95% of measured requests finish. **Idempotency:** safe repeat handling so the same intended operation does not create duplicate effects.
- **STT / TTS:** speech-to-text / text-to-speech. **PWA:** an installable web application with supported progressive capabilities. **Serverless:** managed execution without maintaining a dedicated application server process yourself.
